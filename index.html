    Current research

    Active Vision on Reduced Hardware

    In progress · 2026

    Can a segmentation model look at less of each frame and still see enough? I add a foveation layer on top of existing real-time backbones (PIDNet-S, BiSeNetV2): a low-resolution context view, high-resolution glimpses picked by a gaze policy, and optionally a persistent memory of the scene. Each variant is judged end to end on a single T4 GPU against the full-frame accuracy–latency curve on Cityscapes-VPS video.

    Findings so far

    Method 1Full frame
    ReferenceThe pipeline reproduces the published Cityscapes val scores of both backbones (PIDNet-S 78.76 vs 78.8, BiSeNetV2 74.95 vs 74.95).
    Method 2Glimpses, no memory
    NegativeThe best configuration (0.5 context + 4 glimpses of 384 px) is −0.5 mIoU at equal latency, about 7.7 ms slower at equal mIoU.
    Method 3Motion-gated reuse
    NegativeDeciding what to recompute costs about 6.8 ms, and a one-frame-old prediction already loses about 5 points.
    Method 4Persistent canvas
    StoppedEven a free oracle selector reaches only −0.85 mIoU at equal latency, against a +1.0 pass rule fixed before the runs.

    What it says

    On a T4, a full frame at a slightly higher scale is cheap, and glimpses lack the context the backbone needs. The ceiling is the glimpse itself: a frozen model on crops stays below the same model on the whole frame, whatever is selected or remembered. The next question is whether a single pass on a non-uniformly resampled frame (no crops, no second pass) can escape that ceiling.
